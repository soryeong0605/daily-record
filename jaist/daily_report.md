교수님 랩미팅 정리 (7/17)  
위치제어 vs 속도제어  
교수님이 예전에 하신 작업은 위치제어 방식이었음. 마우스를 세게 누르든 약하게 누르든 상관없이, 항상 정해진 거리만큼(예: dt마다 10cm 이하)을 일정한 속도/가속도로 움직이게 하는 방식. 내가 지금 하는 건 속도제어라서 마우스 세게 누르면 빠르게 나가는 방식인데, 이게 다른 점.
교수님은 franka에 위치제어가 적합한지는 본인도 모르겠다고 하심 — 둘 다 해보고 어떤 게 더 안정적인 모션인지 확인해보라고 하심. 속도제어를 계속 하고 싶으면 해도 된다고는 하셨음.  
핵심 이유: 좋은 시연(demonstration)은 부드러운 모션만 포함해야 함. 빨라졌다 느려졌다 다시 빨라지는 건 안 좋음. 속도제어를 하면 물체에 가까워질 때 속도를 줄여야 하는데(스페이스 마우스를 뒤로 젖히거나 살짝 밀어서), 이렇게 세게 밀었다 약하게 밀었다를 사람 손으로 정교하게 반복하는 게 너무 어려움. → 이건 로봇 문제가 아니라 사람이 clean한 시연을 만들기 어려운 문제.  
위치제어면 그냥 마우스를 항상 최대로 밀기만 하면 되니까(일정 거리만 이동하니까) 사람이 힘 조절 신경 안 써도 됨. 그래서 산업에서 속도제어가 널리 쓰이는 이유이기도 하지만, 교수님 목표는 "사람이 로봇 조종하는 걸 쉽게 만드는 것"이라 위치제어가 나을 수도 있다는 뉘앙스.  
(오픈스페이스에서 로봇이 아는 정보는 위치 정보라고 하심 — 물체의 상대 위치, 사람 위치도 시간에 따른 위치 정보인데, 근데 우리가 로봇에 실제로 주는 명령은 속도라서 이 둘을 처리해야 한다는 얘기도 하셨는데 정확히 뭔 말인지는 좀 애매함.)  
결론: 위치제어 속도제어 둘 다 구현해서 비교해보기. 뭐가 더 조작하기 편한지 직접 확인.

Q2. 관절 토크값을 모방학습 데이터로 넣을 가치가 있는지  
토크가 중요한 정보인 건 맞는데, 실제로 모방학습에 좋은 데이터일지는 모르겠다고 하심. 토크값 없이 학습 vs 포함해서 학습, 두 개 비교해보면 알 수 있을 거라고.  
(우리 로봇에 센서가 없어서 어쩌고 하시는 부분 있었는데 잘 안 들려서 정확히 뭔 말인지 모르겠음)  
이전에 교수님이 쓰신 모방학습 데이터는 이미지였는데, 이미지가 어느 정도는 그런 정보를 대신 줄 수 있다고 함. 근데 예시로 든 상황: 로봇이 물체를 들어올릴 때, 물체 무게 때문에 팁이 아래로 처지면서 카메라 시야를 벗어날 수 있음 → 그럼 카메라는 "물체 없음"으로 인식할 수도 있고 → 모델이 "어 떨어졌나?" 착각해서 파지 동작을 다시 실행할 수도 있음 → 근데 만약 bending moment(힘) 정보가 있으면 "팁에 mass가 실려있다 = 아직 쥐고 있다"는 증거가 계속 남아있어서 모델이 헷갈리지 않을 것.  
단, global vision capture system이 있으면 이 문제 자체가 필요 없어질 수도 있음 (카메라가 안 놓치니까).  
핵심: 모델이 헷갈리는 이유 = 정보의 결핍(lack of information). 이미지는 "물체 없다"고 보여주는데 실제론 있는 상황 = 그 결핍을 메꿔줄 정보를 넣어야 함.

#1 feedforward 제어 vs Feedback 제어  
1) feedforward: 순수 inverse kinematics, 한번 계산하고 끝임
목표 위치 정하기 -> IK계산 (압력-> pwm계산 한번에 계산) -> 그 PWM갑을 로봇에 보냄 -> 끝(실제로 그 위치에 도달했는지 확인 안 하고 끝)

2)feedback방식: PID+IK를 계속 반복  
목표위치 정하기->PID+IK계산 (pwm계산)->로봇에게 보냄 -> 로봇이 해당 pwm의 motion -> 실제위치, position 측정 -> 목표위치와 실제위치 오차를 계산 -> 그 오차를 다시 PID + IK 계산에 넣음  
PID: 오차를 보고 얼마나 보정해야하는지 계산  
IK: PID가 계산한 보정된 목표를 찾아서 PWM 값을 뱉음  

#2 free load VS Mixed load  
1)PID control with free load -> 큰오차 , load있는 경우의 데이터를 포함하지 않음  
2)PID control with mixed load -> 적은 오차, load 있는 경우의 데이터를 포함함  
->두개의 차이가 그냥 게인값으 차이인가, 아니면 뭔가 보정하는 식이 있는건가..?

"옵티로 여러 점 찍어서 PWM-pressure-position 관계식 만들고, 그걸 믿고 피드포워드로 간다" — 이 방향이 모방학습 데이터 수집 + 배포 관점에서 가장 깔끔해.

왜 1번(옵티 게인 → RealSense로 그대로 이식)이 별로인가
OptiTrack에서 튜닝한 P/I/D 게인은 OptiTrack 특유의 노이즈 특성, 업데이트 주기, 지연시간에 맞춰진 값이야. RealSense 기반 위치 추정으로 바꾸면 노이즈/지연이 완전히 달라지니까 게인을 그대로 못 씀 — 사실상 다시 튜닝해야 함
더 근본적으로, RealSense로 실시간 위치 추정 자체가 또 하나의 연구 문제야. 마커 트래킹이든 비전 기반 포즈 추정이든, 그리퍼가 회전(뒤집기)하거나 물체를 잡아서 시야가 가려지면 추정이 끊기거나 부정확해짐 (전에 얘기했던 "파지 시 벨로우 처짐으로 카메라 시야 벗어남" 문제랑 똑같은 리스크)
즉 배포 시점에 RealSense 기반 실시간 폐루프 제어를 유지하려면, 위치 추정 파이프라인 자체를 새로 만들고 검증해야 하는 부담이 생겨
왜 3번(피드포워드)이 모방학습 관점에서 더 좋은가
배포 시점에 외부 트래킹이 전혀 필요 없어짐 — OptiTrack도 없고, RealSense 기반 실시간 위치 폐루프도 없이, 그냥 "목표 위치 → (로드 보정된) PWM"만 계산해서 던지면 끝. 이게 정확히 future work에 있던 MLP(PWM, flow, K → MLP → position) 계획이랑 맞아떨어져
액션 레이블이 더 깔끔해짐 — 만약 실시간 PID로 매 순간 보정하면서 데이터를 모으면, 그 순간의 노이즈/오차에 따라 실제로 보낸 PWM 값이 매번 미묘하게 달라져 (전에 얘기했던 "analog 모드가 손떨림 노이즈를 데이터에 그대로 넣는다"는 우려랑 같은 구조의 문제야). 피드포워드는 같은 목표 위치면 같은 PWM이 나가니까 액션이 훨씬 일관되고 재현 가능함
네가 짚은 대로 정밀도 요구치가 낮음 — rigid robot 수준의 정밀함이 필요 없는 파지 작업이면, 옵티트랙으로 미리 잘 캘리브레이션된 피드포워드 모델의 오차 정도는 충분히 감당 가능할 가능성이 높아
트레이드오프 (숨기면 안 되는 부분)
피드포워드는 캘리브레이션할 때 안 본 조건(예: 훨씬 무거운 물체, 다른 각도)에서는 오차가 커질 수 있어 — 폐루프처럼 실시간으로 스스로 보정 못 하니까
